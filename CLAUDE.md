# POP CLI

`pop` — a CLI for the POP (Proof of Participation) protocol. TypeScript, yargs, ethers v5.

This repo also contains `packages/agent/` (`@poa/agent`), an autonomous governance agent that *uses* this CLI.
Agent architecture, runtime layout, and commit-attribution rules live in
[`packages/agent/CLAUDE.md`](packages/agent/CLAUDE.md) and load automatically when you work in that directory.
Nothing in this file applies to agent runtime concerns, and vice versa.

## Project Structure

- `packages/core/` — **`@poa/core`**: the browser-pure protocol layer (tx intent
  builders, subgraph reads, metadata builders, ABIs, chain config) shared with
  frontends and integrators. See [`packages/core/README.md`](packages/core/README.md).
  Its export surface is a semver contract enforced by `packages/core/api-surface.json`
  + `yarn --cwd packages/core api:check`; purity and calldata parity are test-enforced.
- `src/commands/` — one directory per domain (`task/`, `vote/`, `org/`, `treasury/`, …)
- `src/lib/` — CLI-side infrastructure. Modules that moved to core
  (`payout`, `perms`, `zkemail`, `encoding`, `tx`, `subgraph`, `resolve`, …) are
  thin shims re-exporting `@poa/core` with `process.env`/fs bound — keep them, the
  agent deep-imports `@poa/cli/lib/*` and tests mock these paths. Genuinely
  CLI-only: `output.ts`, `command.ts`, `prompt.ts`, `signer.ts`, `idempotency.ts`,
  `envfile.ts`, `env-load.ts`, `default-org.ts`, `no-alloc-cache.ts`, `audit-db.ts`.
- `src/queries/` — shims over `@poa/core/graph/documents/*` (documents live in core)
- `src/abi/` — contract ABIs, regenerated by `scripts/extract-abis.mjs`; core's
  `gen-abis.mjs` derives its TS ABI modules from these at build time
- `src/config/networks.ts` — shim over `@poa/core/chains` binding process.env
- `test/` — vitest, mirroring `src/` (vitest.config aliases `@poa/core` to core
  SOURCE so tests share one module graph — don't remove that alias)
- `docs/reference/cli/` — command reference, verified by `test/docs/doc-commands.test.ts`

New shared logic goes in `packages/core` (browser-pure, env injected); new
CLI-only concerns (terminal UX, env wiring, disk state) stay in `src/lib`.
Adding a core export is fine; renaming/removing one breaks the api-surface
check and requires a major bump.

## Build and Test

```bash
yarn install && yarn build && yarn test
node dist/index.js --help
```

All commands are `pop <domain> <action>`. Global flags: `--org`, `--chain`, `--json`, `--dry-run`.
Set `POP_DEFAULT_ORG` and `POP_DEFAULT_CHAIN` to avoid repeating them.

## Safety: write commands broadcast real transactions

Write commands sign and broadcast to **Gnosis mainnet** using the key in `~/.pop-agent/.env`.
There is no testnet guard and no confirmation prompt, and several commands read like inspection
commands but are not — `vote announce-all` and `vote execute` both broadcast.

Use `--dry-run`, or ask, before running anything that can write. Read-only verification
(`list`/`status`/`view`/`--json`) is always safe. When delegating to subagents, say this
explicitly — it is not inferable from the command names.

## Architecture: subgraph first, RPC only when necessary

Prefer the subgraph for anything queryable. Legitimate reasons to use RPC:

- writes, gas estimation, and `callStatic` pre-flights whose purpose is to **predict a revert**
  (subgraph lag there means broadcasting a doomed transaction)
- native balances, block numbers, chain time
- ERC20 metadata for arbitrary tokens
- contracts outside the subgraph's data sources (EntryPoint, third-party Governors, ERC-8004)

Everything else should be a subgraph read.

**A field existing in the schema does not mean it is populated.** Several fields are non-null in
the schema but null or zero on every live row. Before depending on one, run a live query proving
real data — converting to an unpopulated field silently turns real values into blanks.

### Subgraph client

`src/lib/subgraph.ts` exposes `query()`, `queryWithFieldFallback()`, `queryUrl()`, `queryAllChains()`.

GraphQL validates a document as a whole, so one unknown field fails the entire query. When a field
may be absent on an older deployment, add a tier to `queryWithFieldFallback()` rather than writing a
bare query — **Arbitrum and Gnosis run different deployments**.

## Conventions

- Metadata JSON key order must match the frontend exactly, or the subgraph and UI break —
  canonical builders live in `@poa/core/metadata/*`; never hand-build metadata objects
- Write commands return `explorerUrl` and entity IDs in `--json` output
- `--json` output shape is a contract: agents parse it. Adding fields is fine; renaming,
  reordering, or removing is not. ENFORCED: promised keys live in
  `docs/reference/cli/output-contracts.json`, verified live by `yarn contracts:check`
  (release flow, `docs/RELEASING.md`) and structurally in CI
- Error codes: `TX_REVERTED`, `INSUFFICIENT_FUNDS`, `NETWORK_ERROR`, `GAS_ESTIMATION_FAILED`
- Errors go through `src/lib/error-catalog.ts`; exit codes through `src/lib/exit-codes.ts`
- Batch independent contract reads through `src/lib/multicall.ts` — never `await` them in a loop
- The "browser-pure seed" (`payout`, `zkemail`, `perms`, and much more) now LIVES in
  `packages/core` — purity is test-enforced there (`packages/core/test/purity.test.ts`).
  New frontend-ported or shareable logic goes in `packages/core`, never in `src/lib`
